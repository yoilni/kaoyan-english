# kaoyan-english

考研英语长期交互复习库。GitHub Pages：`https://yoilni.github.io/kaoyan-english/`

## 维护原则（每次生成/优化前必须阅读）

本 README 是项目的**功能契约 / 防回归清单**。以后无论生成新日期页面、重写文章、修改 `app.js` / `style.css`，都必须先检查本文；优化新功能时不得删除已有功能。若新设计与旧功能冲突，优先保留学习功能，再调整实现。

## 每日内容规则

- 每日新增 `days/YYYY-MM-DD.html`，并更新 `index.html` 首页入口。
- 选题轮换：金融与宏观经济、体育产业与竞技运动、前沿科技、创作者经济、AI 及交叉主题。
- 优先参考当天/近期 Reuters、权威机构、研究报告等可信公开资料，核实近期事实；文章需要解释背景、机制、影响、争议/权衡、长期趋势，而非简单新闻复述。
- **词汇池优先，选题其次**：先从尚未作为目标词学习过的考研/CET-6高价值词中建立候选池，再选择能自然承载这些词的主题。不要为了凑词破坏文章自然度。
- 每日恰好 50 个目标新词。生成前检查 `data/vocab-log.json`、增量 vocab-log 文件及已有每日页面，避免把历史目标词再次算作新词。
- 新词以考研阅读常见的中高阶词、CET-6核心/进阶词为主；过于基础的高中词可以出现在正文，但通常不占50个目标词名额。
- **目标词按“独立记忆价值”筛选**：每天50个目标新词原则上至少40–45个为值得独立记忆的核心单词、派生词或熟词生义；真正高价值且不能仅靠字面稳定推断的固定搭配/短语原则上不超过5–10个。
- **普通组合词不占新词名额**：若表达可由组成词直接推断（如 `bargaining power`、`wage premium` 一类透明组合），通常不得作为一个独立目标新词；应把真正值得掌握的核心组成词/熟词生义列为目标词，并将完整组合放入“🟣表达拆解”。
- 不因词形较长就排除派生词：具有独立词义、常见构词规律且对考研/CET-6阅读有价值的派生词仍可进入目标词池。
- 选词优先级：**考研/CET-6核心独立词与熟词生义 > 高频固定搭配 > 学术/新闻高价值派生词 > 可现场推断的临时专业组合词**。
- 复习词按约 +1、+2、+4、+7、+15、+30 天复现，不计入50个新词。
- **绿色掌握词优先排除**：用户长按单词并标记为绿色，表示“完全掌握”。此类词不得再作为未来每日50个目标新词，也原则上退出常规间隔复习池；后续文章应尽量避免刻意安排它们，仅允许为保证自然英文表达而偶然出现。若掌握状态后来被取消，则恢复正常候选/复习资格。

## 完全掌握词与考研总词汇进度

- 正文单词支持**长按切换完全掌握状态**；完全掌握词保持绿色视觉标记。
- 完全掌握状态必须持久保存在 `localStorage` 学习数据中，刷新、重新进入历史文章后仍能识别。
- 同一个单词无论在多少日期出现，只能按一个已掌握词计数，禁止重复累计。
- 首页学习进度中心必须显示**考研总单词量进度**，至少包含 `已完全掌握词数 / 总目标词数` 与百分比/进度条；绿色掌握词计入已掌握数量。
- 当前项目以 **5500 词**作为考研英语总词汇量的学习进度基准。这是学习进度基准，不声称所有考试词表逐字完全一致。
- 取消绿色掌握状态后，应立即从“已完全掌握”数量和考研总词汇进度中扣除。
- 每日生成新文章时，应优先使用可获得的最新掌握词清单，将绿色掌握词从目标词和常规复习词候选中排除。若自动生成环境无法读取浏览器本地 `localStorage`，不得假装已同步；应使用已同步/导出的掌握词快照，或仅在浏览器侧维持掌握统计，直到建立可靠同步机制。

## 固定文章架构

采用**一个主题 × 两篇连续短阅读**，而不是一篇超长文章或50个孤立例句：

- Reading A：解释问题/现象及其形成机制。
- Reading B：承接 Reading A，讨论回应、限制、权衡或长期影响。
- 推荐约 12–16 个逻辑段落；每段集中约2–4个相关目标词。
- 50个目标新词全部尽量进入连续正文语境，不单独建立脱离文章的“语境拓展”区。
- 每段只保留一条清晰主要逻辑链。
- **遮词测试**：隐藏目标词后，剩余上下文仍应足以推断其大致语义；否则重写上下文。目标词不能成为句子唯一的信息骨架。
- 优先使用定义、同义解释、因果结果、对比、具体例子帮助猜词。

## 每段必须保留的学习组件

每个 Reading 正文段落后都应有：

1. 🟣 **表达拆解**：解释考研阅读中容易读歪的短语、连接结构、长难句关系；不是简单重复目标词中文释义。
2. 🧠 **段落回忆**：用一个问题要求先恢复段落主旨。
3. **提示1 · 逻辑链**：只恢复因果/对比/递进结构，不直接给答案。
4. **提示2 · 猜词线索**：指出正文中可用于推断词义的定义、同义、反义、结果等线索。
5. **显示答案**：最后才展示本段目标词的准确简明中文义。

学习顺序：`读英文 → 猜蓝色词 → 一句话概括段落 → 必要时看🟣表达 → 提示1 → 提示2 → 答案 → 展开中文翻译核对`。

## 正文单词交互

- 新词：蓝色醒目标记，点击显示/隐藏简明中文义。
- 复习词：使用与新词不同的视觉标记。
- 完全掌握词：长按后变为绿色；再次执行掌握切换可取消。
- 新词和复习词旁均显示准确 IPA + `🔊`。
- 页面必须定义：`window.KAOYAN_NEW`、`window.KAOYAN_REVIEW`、`window.KAOYAN_IPA`、`window.KAOYAN_AUDIO`、`window.KAOYAN_TRANSLATIONS`。
- 页面显示 `新词已查看 x/50` 与 `复习词已查看 x/x`，交互进度保存在浏览器 `localStorage`（`kaoyan_progress_v1`）。

## 中文翻译

- `.article` 下每个真正的英文正文 `<p>` 必须有完整、自然、忠实的中文段落翻译。
- `window.KAOYAN_TRANSLATIONS` 与 `.article` 的直接英文 `<p>` **数量、顺序一一对应**。
- `app.js` 在每段后插入“查看中文翻译”；默认收起；展开后按钮改为“收起中文翻译”。
- 不得把全部译文默认展开，也不要直接把中文译文混入英文正文。

## 发音功能

- 发布前尽量为全部新词和复习词预解析可公开直接访问的 HTTPS 真人词典音频，优先美式，并写入 `window.KAOYAN_AUDIO`。
- 不伪造音频 URL，不擅自重新托管第三方音频。
- 点击 `🔊`：有真人 URL → 立即播放；不存在/加载失败/播放失败 → 立即回退 `speechSynthesis` en-US。
- 运行时不得为了真人音频再异步查询词典 API。
- 页面加载/刷新不得自动朗读。
- 保留“测试 Chrome 发音”按钮，且该按钮必须强制只使用 `speechSynthesis`。

## 文末词表：卡片 + 正文溯源（禁止回归）

“今日50个新词”和“今日复习词”必须是可折叠、适合手机的卡片/分栏词表，不能退化成纯文本。每项至少包含：单词、中文释义、IPA、`🔊`、**正文溯源功能**。

### 正文溯源是固定核心功能

- 点击文末词表中的**单词本身**，调用 `app.js` 的 `traceWordToArticle(word, returnTarget)`，滚动到 `.article` 中该词**第一次出现的位置**。
- 定位后的正文单词需要短暂高亮，便于视觉确认。
- 跳转到正文后显示浮动按钮 **“↩ 返回单词列表”**；点击返回刚才词卡位置。
- 返回按钮当前保留约10秒。
- 新词列表和复习词列表都必须支持该功能。
- 若某复习词当天正文没有出现，应在发布前修正文稿；不能静默让溯源失效。
- 每次修改 `app.js`、词表 HTML 或每日页面后，都必须检查溯源没有丢失。

## app.js 全站能力

全站 `app.js` 负责并应持续保留：正文目标词/复习词动态交互标记；IPA 与发音按钮；真人音频优先、TTS兜底；中文翻译展开/收起；新词/复习词查看进度；localStorage 长期学习记录；**长按绿色完全掌握状态及跨页面持久化**；**考研5500词总进度统计**；文末词表卡片增强；**文末词表 → 正文第一次出现位置的溯源跳转**；**正文 → 文末词表的10秒返回按钮**；**全站浮动“↑ 回到顶部”按钮**（页面向下滚动约500px后出现，且不得遮挡返回词表按钮）；首页学习进度统计、弱词等已有能力。

## 数据文件

- `data/vocab-log.json` 是长期目标词历史的主要数据源；不得基于截断内容覆盖它。
- 如果工具无法安全读取完整主日志，可先写日期增量日志 `data/vocab-log-YYYY-MM-DD.json`，之后在能够安全完整读取时再合并。
- 每日记录至少要能追踪新词首次学习日期和复习阶段。
- 掌握词若未来建立仓库侧同步文件，应采用独立、可安全更新的数据文件，不得用浏览器本地状态覆盖公共词汇历史日志。

## 每日发布前防回归检查

发布前逐项确认：

- [ ] 50个目标新词未与历史目标新词重复
- [ ] 已同步的绿色完全掌握词没有被重新选为目标新词或常规复习词
- [ ] 复习词符合间隔计划且实际出现在正文
- [ ] Reading A / B 连续且逻辑自然
- [ ] 每段有🟣表达拆解
- [ ] 每段有主旨 + 提示1 + 提示2 + 答案，按钮实际可展开
- [ ] 目标词通过“遮词测试”，上下文足够猜大意
- [ ] `KAOYAN_NEW / REVIEW / IPA / AUDIO / TRANSLATIONS` 均存在
- [ ] 所有新词/复习词有 IPA
- [ ] `KAOYAN_AUDIO` 仅含合法 HTTPS URL；缺失项能立即 TTS 兜底
- [ ] 每个正文英文 `<p>` 有一一对应中文翻译，默认收起
- [ ] 文末新词/复习词均为交互卡片，不是纯文本
- [ ] 文末词卡显示中文、IPA、🔊
- [ ] **点击文末新词可溯源到正文**
- [ ] **点击文末复习词可溯源到正文**
- [ ] 跳转正文后出现“↩ 返回单词列表”，可返回原词卡
- [ ] 页面下滚后出现“↑ 回到顶部”，点击可平滑返回顶部，且不遮挡“↩ 返回单词列表”
- [ ] 新词/复习进度计数正常
- [ ] 长按目标词可切换绿色完全掌握状态，刷新后仍保留
- [ ] 同一掌握词在考研总词汇进度中只计一次；取消掌握会扣除
- [ ] 首页显示 `已掌握 / 5500` 与总词汇学习百分比/进度条
- [ ] “测试 Chrome 发音”正常且强制 TTS
- [ ] 首页入口、历史文章列表、缓存版本号同步更新
- [ ] vocab log 安全更新，绝不使用截断数据覆盖主日志

## 修改流程

以后每次优化项目按以下顺序执行：

`读取 README.md → 读取当前 app.js/style.css → 读取待修改页面 → 对照防回归清单 → 修改 → 再检查关键功能 → 提交`

新增功能应同步补充到本 README 的“功能契约”和检查清单中，使后续版本默认继承，而不是靠聊天上下文记忆。
